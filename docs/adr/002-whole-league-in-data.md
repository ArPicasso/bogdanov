# ADR-002. Вся лига: команды живут в данных, а не в коде

Статус: принято, 24.09.2026

## Контекст

Продукт строится под всю РХЛ, а не под один клуб. Сейчас «Рязань-ВДВ» зашита в тексты
бота и в `games.json`. Официальный сайт РХЛ `rhl.fhr.ru` на 24.09 закрыт, полный календарь
ФХР в открытом виде не найден. У нас есть официальный состав участников (`calendar.pdf`,
стр. 2) и официальный календарь только «Рязани» (`games.json`).

## Решение

1. **`teams.json` — справочник команд.** 26 команд из официального состава, с конференцией,
   городом и всеми вариантами написания (у лиги, агрегатора и в `games.json` названия разные).
   Новая команда или переименование — правка данных, не кода
2. **`webapp/data/league.json` — единая выгрузка.** Команды, все матчи сезона, результаты,
   таблица по конференциям. Собирает `build_data.py`, читают мини-апп и бот
3. **Календарь лиги — временно из `r-hockey.ru`.** Другого открытого источника нет. Матчи
   помечаются `official: false`. Проверка 24.09 нашла ошибки: у пяти команд 46 игр, у пяти
   49–50 — часть матчей приписана не тем командам. Поэтому:
   - где есть официальный календарь (сейчас — «Рязань», `games.json`), он заменяет агрегатор
   - когда откроется `rhl.fhr.ru`, календарь переезжает на него, агрегатор остаётся для сверки
4. **Результаты — только из протоколов лиги** (ADR-001). `league.py` учится качать протоколы
   всего турнира, а не одного клуба
5. **Таблица считается из результатов** по правилам лиги: победа в любое время — 2 очка,
   поражение в ОТ или по буллитам — 1, в основное время — 0. Проверено на таблице НМХЛ 2025/26

## Последствия

- `CLAUDE.md` «агрегаторы только для сверки» получает исключение: календарь других команд
  до открытия сайта РХЛ. В интерфейсе такие матчи не выдаются за официальные
- Формат `games.json` не меняется, он остаётся официальным календарём «Рязани»
- Подписки бота должны стать подписками на команду. Это меняет `subscribers.json` и делается
  отдельной задачей
