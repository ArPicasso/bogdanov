# ADR-006. История очных встреч в карточке матча

Статус: принято, 25.09.2026 — запрос владельца продукта

## Контекст

Болельщик открывает карточку будущего матча, например «Рязань-ВДВ» — «Белгород», и видит
только дату и город. Главный вопрос перед игрой — «мы фавориты или нет?» — остаётся без ответа.
Самый понятный ответ в хоккее — история очных встреч: кто сколько выиграл, сколько забил и
пропустил, чем кончились последние игры.

Что есть в источниках (проверено 25.09.2026):

- На `nmhl.fhr.ru` открыт архив турниров с 12/13. Страница календаря турнира
  `/calendar/<id>/` отдаёт **все** матчи с датой, командами и счётом, включая «ОТ» и «Б».
  Один запрос на турнир: 25/26 — 624 матча, 24/25 — 528, 23/24 — 484
- Протоколы для этого не нужны: хватает строки календаря. Протоколы остаются источником
  текущего сезона (ADR-001)
- Часть клубов играла под другими названиями: «Воевода» → «Витязь-Подольск», «Гранит-Чехов»
  и «Гранит» → «Ахмат-Гранит» (переименования подтверждены статьями Википедии о РХЛ и
  об «Ахмат-Граните»). Новички из МХЛ и ВХЛ («Динамо-Карелия», «Ростов») в НМХЛ не играли
- Страница плей-офф 25/26 без фильтра по клубу отдаёт пустую таблицу — у плей-офф календарь
  нужно брать иначе, это выясняется при реализации

## Решение

1. **`history.py`** — загрузка календарей прошлых сезонов с сайта лиги: регулярный чемпионат и
   плей-офф, по одному запросу на турнир, с паузой в секунду, как `league.py`. Разбор — тем же
   мини-DOM из `league.py`
2. **Глубина — пять прошлых сезонов** (21/22–25/26). Дальше составы полностью сменились, и
   старые счета о силе команды не говорят. Глубина — параметр, а не константа в коде
3. **`history.json` в git.** Прошлые сезоны не меняются, файл собирается один раз и
   пересобирается руками. Команды в нём уже приведены к id из `teams.json`; матчи команд,
   которых нет в РХЛ-2026/27, отбрасываются
4. **Прежние названия — поле `former` в `teams.json`.** Отдельно от `aliases`: алиасы — это
   написания текущего клуба, `former` — его прошлые имена. Вносим только подтверждённые
   переименования. Неподтверждённые («Хорс Подольск», «Факел») не связываем: лучше «раньше
   не встречались», чем чужая история
5. **`webapp/data/h2h.json` — отдельный файл**, собирает `build_data.py`. Для каждой пары
   команд, которая встречается в календаре 2026/27: победы каждой стороны, забитые и
   пропущенные, пять последних встреч со счётом. Мини-апп грузит его только при открытии
   карточки матча, чтобы не утяжелять первый запуск. Встречи текущего сезона добавляются
   из `results.json` при каждой сборке
6. **В карточке матча — блок «Очные встречи».** Счёт побед «5 — 2», голы «21:14», пять
   последних игр строками. Под ним — одна строка вывода, по правилу:
   - меньше трёх встреч — «Встречались мало, фаворита по истории не назвать»
   - иначе фаворит тот, у кого больше побед; при равенстве — «История равная»
   Формулировка — «по истории встреч», а не «фаворит»: прогноз мы не даём
7. Нет ни одной встречи — блок пишет «В НМХЛ и РХЛ раньше не встречались»

## Последствия

- Карточка будущего матча перестаёт быть пустой: это главный вход в мини-апп из напоминания
- Появляется второй внешний запрос к сайту лиги, но разовый: прошлые сезоны не меняются
- Переименование клуба теперь правится в двух местах данных — `aliases` и `former`
- Сила по таблице текущего сезона (место, форма) в блок не входит: до первых туров её нет.
  Добавим к выводу, когда сыграют 5 туров
