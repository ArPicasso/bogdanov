# ADR-001. Результаты матчей берём из протоколов лиги

Статус: принято, 24.09.2026

## Контекст

Этап 3 плана — счёт после матча и таблица. Разведка (`docs/research/2026-09-24-stage1-data.md`)
показала, что лига публикует протокол каждого матча: счёт по периодам, голы с авторами и
передачами, составы, посещаемость. Сайт РХЛ `rhl.fhr.ru` на 24.09 закрыт, архив НМХЛ
`nmhl.fhr.ru` открыт, движок у них, по всей видимости, общий.

## Варианты

1. **Парсер протоколов лиги.** Данные официальные и полные. Риск: вёрстка может поменяться,
   новый сайт ещё не видели
2. **Агрегатор `r-hockey.ru`.** Уже есть сезон 2026/27. Но в календаре не хватает двух игр
   из 48, и это чужая переработка данных лиги
3. **Ручной ввод через админку.** Надёжно, но это работа человека после каждого матча, которую
   никто не взял на себя

## Решение

Вариант 1. Модуль `league.py` скачивает и разбирает протоколы, результат кладёт в
`results.json`. Ключ связи с `games.json` — номер матча в календаре лиги (`n`), он же
«Матч № N» в протоколе. В плей-офф нумерация начинается заново, поэтому в файле
результаты разложены по id турнира. Формат `games.json` не меняется.

Детали:

- Адрес сайта, id турнира и id клуба в сезоне — параметры, а не константы: для 2026/27
  они станут известны, когда откроется `rhl.fhr.ru`
- Без новых зависимостей: `html.parser` из стандартной библиотеки и `aiohttp`, который
  уже ставится с aiogram
- Время начала в протоколе — местное для арены (в Ангарске 12:00), поэтому хранится строкой
  рядом с датой, а не как `datetime` по Москве
- Парсер не падает на незнакомой странице, а возвращает `None`: протокола ещё нет или
  вёрстка поменялась. Второе ловят тесты на сохранённых страницах
- Запросы к сайту лиги — последовательно, с паузой. Сайт не наш, нагружать его нельзя

## Последствия

- Как только откроется `rhl.fhr.ru`, первым делом прогнать парсер на его протоколе.
  Если вёрстка другая — чинить разбор, тесты покажут где
- Агрегатор остаётся только для сверки
- Живых событий матча протокол не даёт. Push на гол — отдельное решение (этап 4)
