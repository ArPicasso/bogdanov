# ADR-009. Лидеры лиги: лучшие игроки по статистике

Статус: принято, 25.09.2026 — запрос владельца продукта

## Контекст

Болельщик заходит в «Таблицу», смотрит место своей команды и хочет следом увидеть, кто
лучший в лиге: бомбардиры, снайперы, плюс-минус, вратари. Топ-10 по каждому показателю.
Сезон 2026/27 начинается 3 октября, сайт РХЛ закрыт, поэтому начинаем с прошлого сезона.

Что есть в источнике (проверено 25.09.2026 на `nmhl.fhr.ru`, у `rhl.fhr.ru` тот же движок):

- **`/stat/leaders/<турнир>/<показатель>/`** — готовые списки лиги, по 30 игроков: бомбардиры
  `pts`, снайперы `g`, ассистенты `a`, плюс-минус `pm`, штраф `pim`, победные голы `gwg`,
  вратари по проценту отражённых `sv_pct` и по коэффициенту надёжности `gaa`. В строке — место,
  игрок со ссылкой `/players/<id>/`, клуб, амплуа, номер и цифры: И, Ш, А, О, +/-, Штр; у
  вратарей — И, В, П, %ОБ, КН, «сухие», время
- **`/stat/players/<турнир>/`** — все игроки лиги одной страницей (около 940), 700 КБ.
  Колонок больше: броски, реализация, голы в большинстве и меньшинстве, вбрасывания
- **Блокированных бросков в источнике нет** — ни в лидерах, ни в статистике игроков, ни в
  протоколе. Показать их нечем

Вратарей в списке лидеров лига отбирает по своему порогу игрового времени (в 25/26 в список
попал вратарь с 852 минутами, не попал — с 514). Порог нигде не опубликован.

## Решение

1. **Источник — страницы лидеров лиги.** Шесть показателей — шесть запросов по одному в
   секунду: бомбардиры, снайперы, ассистенты, плюс-минус, вратари (%ОБ), штраф. Места и
   порядок берём как у лиги: не угадываем ни порог для вратарей, ни правило при равенстве
   очков. Общую статистику игроков (`/stat/players/`) не берём: она нужна составам (ADR-007),
   для лидеров хватает готовых списков
2. **`league.py --leaders`** пишет `leaders.json`: турнир, его название и по 30 строк на
   показатель. Сезон берётся так же, как для протоколов, — последний регулярный чемпионат на
   сайте лиги. Если у сезона ещё нет статистики, файл не трогаем
3. **`leaders.json` в git**, как `history.json`: сейчас в нём НМХЛ 2025/26. Когда появится
   переменная `LEAGUE_SITE`, задание мини-аппа раз в час запрашивает лидеров нового сезона.
   Как только после первого тура у РХЛ появятся списки, файл заменится ими, до этого остаётся
   прошлый сезон
4. **`build_data.py`** собирает `webapp/data/leaders.json`: топ-10 каждого показателя и, для
   каждой команды, её лучшего игрока с 11-го по 30-е место — чтобы болельщик видел «своего»,
   даже если тот не в десятке. Клуб прошлого сезона приводится к нынешнему id по `teams.json`,
   с прежними названиями (как в ADR-006); клубы, которых в РХЛ нет, остаются названием без
   эмблемы. Id игроков в мини-апп не выгружаем, `hidden_players.json` действует (ADR-007, 008)
5. **Экран «Таблица»**: в шапке сегменты «Команды · Игроки». «Команды» — как было, с
   конференциями. «Игроки» — пилюли показателей, список топ-10: место, фамилия и имя, эмблема
   и клуб, цифры, выбранная — жирным. Игроки любимой команды — строкой `--sel`. Если своих в
   десятке нет, под пунктиром «лучший в команде» — её лучший игрок из тридцати. Над списком —
   чей сезон: «НМХЛ 2025/26 · прошлый сезон», пока новый не начался. Файл лидеров грузится при
   первом открытии «Игроков», как `h2h.json`
6. **Колонки**: бомбардиры, снайперы, ассистенты — И, Ш, А, О; плюс-минус — И, О, +/−;
   штраф — И, О, Штр; вратари — И, КН, %ОБ. Внизу — расшифровка сокращений и источник

## Чего не делаем

- Блокированные броски — нет в источнике
- Свой расчёт лидеров из протоколов — лига уже публикует рейтинг, свой разойдётся с ним
- Лидеры плей-офф и прошлых сезонов с выбором сезона — пока нет запроса
- Карточку игрока по нажатию — её даст ADR-007 вместе с составами

## Последствия

- Каждый час, когда задан `LEAGUE_SITE`, ещё шесть запросов к сайту лиги, около шести секунд
- В мини-аппе один новый файл, около 10 КБ, грузится только на вкладке «Игроки»
- Пока идёт межсезонье, болельщик видит прошлый сезон с явной подписью — часть игроков
  уже вышла из возраста U21, клубы в нём под нынешними названиями
